# Laravel School

A personal publication about Laravel. An author writes markdown files and pushes
them to `main`; the site serves them. There is no CMS, no admin panel, and no
editorial workflow beyond git.

## Language

### Content

**Document**:
Any single markdown file the site can render as a page. The superset of Post,
Snippet, and Page, and the only thing a human writes.
_Avoid_: article, entry, item. (The Blade views currently say `$document` on show
pages and `$article` in listings for the same concept — one of them is wrong.)

**Post**:
A long-form Document. Appears in the main feed.

**Snippet**:
A short-form Document — a tip, a command, a fragment. Has its own feed. A
Document's directory decides whether it is a Post or a Snippet; its Category no
longer does.
_Avoid_: note, TIL.

**Page**:
A standing Document with no date and no place in any feed, reachable only from
navigation. "About me", "Uses".
_Avoid_: static page.

**Frontmatter**:
The YAML block at the head of a Document. The author's only interface for
describing a Document to the site, and the boundary between authored truth and
derived truth: everything under Frontmatter was written by a human.

**Document Key**:
The number that names a Document's file (`99.md` → `99`). Assigned by the author,
never reused, and stable regardless of how the Document is later retitled.
_Avoid_: id, post number.

**Slug**:
A Document's permanent public address, declared explicitly in Frontmatter and
never derived from the title. A Slug is a promise: once published it must not
change, because inbound links and search rankings depend on it. Retitling a
Document does not change its Slug.
_Avoid_: permalink, URL, path.

**Category**:
Exactly one per Document, naming its topic. Names a topic only — never a kind of
Document.
_Avoid_: type, section.

**Tag**:
Zero or more per Document. Finer-grained than Category.

**Excerpt**:
The author's own summary of a Document, used in feeds and as the meta
description. Never generated by truncating the body.
_Avoid_: description, summary, teaser.

### Publishing

**Publish**:
Committing a Document to `main` and pushing. This is the author's entire
publishing interface — pushing markdown *is* publishing. Any step required
before or after the push is a defect, not a workflow.
_Avoid_: deploy, release.

**Build**:
The step that regenerates every Derived Artifact from the Documents. Runs on the
server after a deploy, and always rebuilds everything from source rather than
updating incrementally, so no Derived Artifact can disagree with the Documents.

**Derived Artifact**:
Anything the site needs that is computed from Documents rather than written by
the author: the Index, the sitemap, the RSS feed, the search index, OG images,
rendered HTML. A Derived Artifact is never authored, never committed, and never a
source of truth — it can always be discarded and rebuilt.
_Avoid_: build output, generated file, cache.

**Index**:
The projection of every Document's Frontmatter, used to build feeds and filter by
Category and Tag without reading every file from disk. A Derived Artifact.
_Avoid_: database, catalog.
